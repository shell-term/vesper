# Vesper（ヴェスパー）

元のモデルの精度を保ち、GPU・RAM・SSDを組み合わせて大きなMoEモデルを動かすためのプロジェクトです。
最初の対象はDeepSeek-V4.1-Flash-1017、RTX 4090＋RTX 3080 Tiです。

進捗は[Issues](https://github.com/shell-term/vesper/issues)と[Milestones](https://github.com/shell-term/vesper/milestones)で管理します。
「実装済み」と「公式との一致を検証済み」を区別し、合格条件と測定データを各Issueに残します。
[開発の節目と運用方針](docs/roadmap.md)も公開しています。

元のゲートからキャッシュ・expert・出力合算までを接続し、**実際のモデルから取得した入力でも検証が通りました**。
4入力・text/image両方のゲート設定で30実行すべてが公式と108段階の中間値まで一致し、
メモリ不足・転送破損・読み込み失敗からの再実行も一致しています。
PyTorchなしの環境でも全検証を再現しました。これはM1のMoE部分の検証で、文章生成は未完了です。
[実入力の検証レポート](docs/real-moe-validation.md)と[Issue #6](https://github.com/shell-term/vesper/issues/6)に記録します。

AttentionのQueryの置き場所だけを変える候補を実装し、64ヘッド・512次元を4090で実行できました。
GPU内の作業領域は138 KiBから74 KiBに減り、比較可能な小さい構成では中間値も公式と一致しました。
公式が生成した演算命令を保持し、メモリの読み書きだけを変更した比較経路を別に検証しました。
実寸構成でも途中値が一致し、この経路から実際のMoE入力を取得できました。
未変更の公式カーネルそのものの起動は、4090の上限を超えるため引き続きできません。
[Issue #7](https://github.com/shell-term/vesper/issues/7)と[比較経路の検証](docs/attention-memory-validation.md)に詳細があります。

共有expertのFP8計算と、expert出力を合算する順序・丸めを検証しました。
共有expertの54条件、合算の38条件、元の6個のexpertと共有expertを組み合わせた16条件で、
中間値と最終出力がすべて一致しています。PyTorchなしの環境でも全108条件を再照合できました。
この合算検証ではルーティング先と重みを指定しています。元のゲートとの接続は上記の別検証で扱います。
詳細は[検証レポート](docs/moe-arithmetic-validation.md)と[Issue #5](https://github.com/shell-term/vesper/issues/5)にあります。

[ゲートの行列計算とルーター](docs/gate-validation.md)をつなぎ、307種類の検証用入力を
text/image両条件で比べた614比較で、出力・expertのID・順序・重みがすべてビット単位で一致しました。
元のBF16重みを保持し、公式と同じFP32計算を使います。推論側にPyTorchは不要です。
対象は指定した参照版の単一トークン処理です。文章生成は未完了です。
[Issue #4](https://github.com/shell-term/vesper/issues/4)に記録しています。

現在は**キャッシュを切り替えながらexpertを動かせる検証用実装**です。まだ文章生成はできません。
元の重みを保持し、公式実装と直接比較しています。

| 検証対象 | 範囲 | 判定 |
| --- | --- | --- |
| RTX 4090のFP8演算 | expert全体・128条件 | 最終655,360出力と検証した中間値がすべてビット単位で一致 |
| SSD・RAM・両GPUのキャッシュ | 異なるexpert三個・232実行 | 最終1,187,840出力と検証した中間値がすべてビット単位で一致 |
| RTX 3080 TiのBF16演算候補 | W1の128行・8入力 | 1,024出力中14個不一致・未合格 |

expert全体の検証には、三つの行列演算、学習時のクリップ、重み付きSwiGLU、途中の丸めを含みます。
入力の大きさと重み付けを変え、GPU上の重みと作業領域を繰り返し使いました。
元の重みは約18.8MB、明示的なGPU確保量は約18.9MBです。CUDAや公式比較環境の使用量は別にかかります。

3080 Tiの差は32要素の積和の時点で発生しています。BF16への置き換えだけでは公式のFP8演算を再現できませんでした。
詳細と省略していない測定データは[expert検証レポート](docs/expert-validation.md)にあります。
他の層・圧縮方式を含むTransformerブロック、モデル全体の品質、文章生成の速度は未検証です。

キャッシュ検証では、3080 Tiを元の重みの保管に使い、計算は4090で行います。
RAM・GPUからの退避、SSDからの再読み込み、空きメモリ不足を模した際の処理拒否と復帰を確認しました。
ホスト側の明示的なバッファは最大約72.7MiBです。Python、CUDA、公式比較環境などの使用量は別にかかります。
実際のルーターではなく決められた呼び出し順による検証です。詳細と全データは[キャッシュ検証レポート](docs/cache-validation.md)にあります。

整合性確認をGPUで行う方式を追加しました。元の重みとの照合を保ちながら、
同じキャッシュ容量・呼び出し順の6組比較で、呼び出し時間が中央値で約5.0倍改善しました。
新方式でも232実行の全検証段階が公式と一致し、バッファ増加は約0.70MiBです。
これはキャッシュに重みが揃った状態の検証で、文章生成速度ではありません。
起動時の準備コストと全測定データは[高速化レポート](docs/cache-performance.md)にあります。

推論全体のRAM上限96GiB・システムの空き32GiBを初期設計としています。
これは将来のエンジンに求める条件であり、推論全体のメモリ制御が実装済みという意味ではありません。
現在のキャッシュにはバッファ上限と、空きメモリ低下時にRAMキャッシュを解放する制御を実装しました。
現在の検証は小さなバッファで行い、他のアプリや推論エンジンを停止しません。

追加の非可逆な量子化、expertの削除、キャッシュに合わせたルーティング変更は採用しません。
公式モデルに元から含まれるFP4/FP8を保持し、途中の丸め処理も確認します。

Attentionの計算本体も、PyTorch・TileLangを入れていない環境で実行できるようになりました。
36条件で、最終BF16出力1,261,568要素と検証した全途中値が、検証済みの公式演算の参照と完全一致しました。
カーネルの事前作成には比較用の環境を使います。続くAttention層全体の検証は下記を参照してください。
詳細と全測定値は[native Attentionレポート](docs/native-attention-validation.md)を参照してください。

KVキャッシュの丸め・128行の更新・再利用・巻き戻しも実装しました。
398回のKV更新と、そこからAttentionにつないだ128条件で、検証した全途中値が参照とビット単位で一致しています。
失敗した更新の破棄と再試行も確認済みです。詳細は[KVキャッシュ検証](docs/window-kv-validation.md)にあります。
この検証の入力はRoPE後の値です。

続いて、元の学習済み重みを使う正規化とRoPEを実装しました。
476の単体条件と、KVまでつなぐ56条件で、検証した全途中値がビット単位で一致しました。
うち46条件ではAttention・逆RoPEまで接続しています。
周波数は二つの元の設定で位置0〜131,071をすべて照合し、PyTorch・TileLangのない環境での再現も通っています。
この段階では投影後の入力からの検証です。
詳細は[正規化・RoPE検証](docs/normalization-rope-validation.md)にあります。

元のQuery・KV・出力投影を接続し、**非圧縮のAttention層0全体**も検証できました。
90の投影条件と309回の層実行（失敗後の再試行5回を含む）で、17,355箇所の比較がすべてビット単位で一致しています。
実際の元モデルから取得した4入力、ウィンドウ2周、失敗時のKV復元も含み、PyTorchなしの再現も通りました。
詳細と全測定値は[Attention層検証](docs/attention-projection-validation.md)にあります。
このAttention層を含むブロック全体の検証は、次の段階で扱います。

Hyper-Connectionsと残差も接続し、**最初のTransformerブロック全体**を実行できました。
HCの84条件とブロック26実行で、6,648箇所の比較がすべてビット単位で一致しています。
各ブロック実行では225段階の途中値に加え、元の実装の出力・次層への係数・KV状態も照合しました。
失敗からの再試行5回と、PyTorchなしでの再現も通っています。
対象は非圧縮の層0・1トークンずつの処理です。圧縮KV・索引・層間共有・Engram・文章生成は未完成です。
詳細と全測定値は[ブロック全体の検証レポート](docs/layer0-block-validation.md)にあります。
